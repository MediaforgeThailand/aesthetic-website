# ตรวจ CI ทั้งเว็บ — ฟอนต์ และ โลโก้

ตรวจเมื่อ 15 ส.ค. 2569 · ครบทั้ง **234 หน้า** (ไทย 117 + อังกฤษ 117) จาก sitemap ทุก URL

วิธีตรวจ: ดึง HTML ที่เรนเดอร์จริงของทุกหน้ามาแยกค่า `font-family` / `font:` / `<img>` ทุกตัว
แล้วให้ผู้ตรวจอิสระ 6 ชุด (cascade · ฟอนต์ตัวที่สาม · น้ำหนักฟอนต์ · การส่งไฟล์ฟอนต์ · โลโก้ · surface อื่น)
ตรวจแยกกัน จากนั้นส่งทุกข้อค้นพบให้ผู้ตรวจอีกชุด **พยายามหักล้าง** ก่อนจะนับว่าเป็นปัญหาจริง
ผลคือ ยืนยัน 13 ข้อ · **หักล้างทิ้ง 4 ข้อ**

---

## คำตอบสองข้อที่ถาม

### 1. ฟอนต์ถูกตาม CI หรือยัง → **ถูกแล้ว ในแง่ที่ประกาศไว้ แต่มี 3 เรื่องที่ยังไม่เรียบร้อย**

สิ่งที่ยืนยันแล้วว่าถูก:

- ทั้ง 234 หน้า ใช้ stack `'Luxia','Noto Sans Thai'` เหมือนกันหมด ไม่มีหน้าไหนหลุด
- ค่า `font-family` ที่ต่างกันในทั้งเว็บมีแค่ **2 ค่า** และ `font:` shorthand 63 แบบ **ลงท้ายด้วย stack เดียวกันทุกตัว**
- **ไม่มีคำว่า DB Heavent เหลือในหน้าไหนเลย** — ตรวจครบ 234 หน้า
- ไม่มี SVG `<text>`, ไม่มีการตั้งฟอนต์จาก JavaScript, ไม่มี `content:` ใน pseudo-element
  แปลว่าไม่มีตัวอักษรที่หลุดออกนอกกฎ CSS
- ไทย/อังกฤษ ใช้ stack เดียวกันเป๊ะ

เรื่องที่ยังไม่เรียบร้อย → ดู **ปัญหาที่ต้องตัดสินใจ** ด้านล่าง

### 2. โลโก้เปลี่ยนเป็นอันใหม่ทั้งเว็บแล้วใช่ไหม → **ใช่ ในโค้ด — แต่โลโก้เก่ายังฝังอยู่ใน "เนื้อภาพ" อีกหลายสิบหน้า**

- `logo-art.png` ขึ้นครบ **234/234 หน้า** (หน้าละ 3 จุด: header + footer เดสก์ท็อป + footer มือถือ)
- `logo-header.png` / `logo-footer.png` ขึ้น **0 หน้า** — และตอนนี้ลบไฟล์ทิ้งแล้ว
- ในทั้งเว็บมีไฟล์โลโก้ที่ถูกอ้างถึงแค่ **ไฟล์เดียว** คือ `logo-art.png`
- สัดส่วนภาพถูกต้อง ไม่มีจุดไหนบีบ/ยืด

**แต่** โลโก้ **"THE ART CLINIC" ตัวเก่า ยังฝังอยู่ในพิกเซลของรูปถ่าย** ที่ใช้เป็นเนื้อหา
อันนี้เปลี่ยนไฟล์โลโก้ไม่ช่วย ต้องแก้ที่ตัวรูป ดูหัวข้อถัดไป

**ทำไมสำคัญ:** คนเข้าเว็บ (และเจ้าหน้าที่ สบส. ถ้ามาตรวจ) จะเห็นโรงพยาบาลใช้ชื่อแบรนด์ที่ตั้งใจเลิกใช้แล้ว

1. **แก้ด้วยการรีทัช (~63 ไฟล์)** — กลุ่ม `review*` / `slide*` ตราเก่าเป็น overlay แบนอยู่มุมภาพ

   รวมเข้ากับงานถ่ายรูปหมอ 6 ใบที่ค้างอยู่แล้ว

> ⚠️ ตำแหน่งตราไม่ได้อยู่มุมเดียวกันทุกไฟล์ **อย่าไล่จากชื่อไฟล์** ให้ไล่ดูภาพจริงทั้งโฟลเดอร์

## ⚠️ ปัญหาที่ต้องตัดสินใจ (ยังไม่ได้แก้ รอเจ้าของเว็บเคาะ)

### A. Playfair Display — ฟอนต์ตัวที่สาม

CI ที่สั่งมาระบุ **สองฟอนต์** คือ Luxia + Noto Sans Thai แต่เว็บยังโหลด **Playfair Display**
จาก Google Fonts **ทั้ง 234 หน้า** ทั้งที่มันวาดตัวอักษรจริงแค่ **26 หน้า** — และวาดแค่
ตัวเลขตกแต่ง `01` `02` `03`, ลำดับใน Top 5, เลขขั้นตอนหน้าหัตถการ และเลข `404`

**208 หน้ายิงขอ Google โดยไม่ได้ใช้อะไรเลย** ทุกครั้งที่มีคนเปิดหน้า IP + User-Agent ของคนนั้น
ถูกส่งไปที่ Google ซึ่งสำหรับเว็บโรงพยาบาลควรเป็นเรื่องที่ตัดสินใจตั้งใจ ไม่ใช่ติดมาโดยไม่รู้ตัว

ทางเลือก: **ตัดทิ้ง** (ตัวเลขตกไปใช้ Luxia ซึ่งเป็นฟอนต์ display อยู่แล้ว) · **เก็บไว้แต่ self-host**
ผ่าน `next/font/google` (หน้าตาเหมือนเดิม ไม่ต้องยิง Google ตอนใช้งาน) · หรือ **เก็บไว้แบบเดิม**

### B. น้ำหนักฟอนต์ไทย/อังกฤษไม่เท่ากัน

Luxia มีน้ำหนักจริงแค่ **400** กับ **500** ส่วน Noto Sans Thai เป็น variable font มีครบ 300–700
เว็บเขียน `font-weight:300` ไว้ **81 จุด** (เป็นน้ำหนักที่ใช้เยอะที่สุดในเว็บ) และ `600` อีก 35 จุด
ผลคือในบรรทัดเดียวกัน:

- **ที่น้ำหนัก 300** — ไทยได้ Light จริง แต่อังกฤษตกไปใช้ 400 → **อังกฤษเข้มกว่าไทยราว 38%**
  เห็นชัดที่คำอธิบายหมวดหัตถการหน้าแรก เช่น *"Ultraformer, Thermage, Pico Laser, เลเซอร์กำจัดขน"*
  ชื่อเครื่องภาษาอังกฤษจะเด้งออกมาเหมือนตั้งใจเน้น ทั้งที่ไม่ได้ตั้งใจ
- **ที่น้ำหนัก 600** — ไทยได้ semibold จริง แต่อังกฤษไม่ขยับเลย (ค้างที่ 500)
  เห็นชัดที่ Top 5 หน้าแรก *"Filler ปาก"* — คำว่า Filler บางกว่าคำว่า ปาก ที่อยู่ติดกัน

ซ้ำร้าย `font-size-adjust:0.5` ที่ทำให้ขนาดตัวอักษรสองภาษาเท่ากัน ยิ่งทำให้ความต่างของ **น้ำหนัก**
เด่นขึ้น เพราะไม่มีความต่างอื่นมากลบ

ทางเลือก: **ล็อกไทยให้เท่าอังกฤษ** (แก้ `font-weight` ของ Noto เป็น `400 500` — สองภาษาตรงกันทันที
แต่ทิ้งน้ำหนัก Light ของไทย) · **ซื้อ Luxia Light + SemiBold มาเพิ่ม** (สวยที่สุด ตรง CI ที่สุด แต่ต้องมีไฟล์ฟอนต์)
· **ปล่อยไว้** ถ้ายอมรับได้

## 📋 ข้ออื่น ๆ (ระดับต่ำ)

- **ไม่มี favicon.ico / apple-touch-icon / web manifest** — ไอคอนเดียวที่ประกาศคือ `logo-art.png`
  ซึ่งเป็นภาพ 549×324 ไม่ใช่สี่เหลี่ยมจัตุรัส เบราว์เซอร์จะบีบให้เอง ไอคอนบนแท็บ/หน้าจอมือถือจะดูเบี้ยว
  → ควรทำไฟล์สี่เหลี่ยมจัตุรัสจากโลโก้ CI แยกต่างหาก
- **ไฟล์ฟอนต์ใน `/public` ไม่ได้ตั้ง cache header** — โหลดใหม่บ่อยกว่าที่ควร
- **หน้า 404 ยังเป็นหน้าเปล่าของ Next** (ตัวอักษร system-ui พื้นขาวดำ ไม่มีโลโก้ ไม่มีเมนู)
  ไฟล์ `app/(th)/not-found.tsx` และ `app/(en)/not-found.tsx` **ไม่เคยถูกใช้งานจริง** เพราะ
  `[slug]/page.tsx` ตั้ง `dynamicParams = false` เว็บเลย 404 ตั้งแต่ก่อนเข้า segment
  และเว็บมี root layout สองอัน ({th} / {en}) จะเพิ่ม `app/not-found.tsx` เฉย ๆ ไม่ได้ Next จะ error
  → แก้ได้แต่ต้องรื้อโครง layout **ไม่ควรทำก่อน go-live** ยกไปทำหลังเปิดเว็บ
  (สำคัญขึ้นถ้าจะใช้ `docs/redirects.csv` เพราะลิงก์เก่าที่ไม่ได้ redirect จะตกมาหน้านี้)

## ข้อที่ตรวจแล้ว "ไม่เป็นปัญหา" (ถูกหักล้าง)

บันทึกไว้กันตรวจซ้ำ:

- **Playfair inline ในหน้า Contact ถูก `!important` ทับ** → ไม่จริง `.aa-root .aa-pfi` ค่า specificity 0,2,0
  ชนะ `.aa-root *` ที่ 0,1,0 — Playfair วาดจริง
- **stylesheet ของ Google อยู่ใน `<body>` ไม่ใช่ `<head>`** → จริงตามตำแหน่ง แต่ไม่ใช่ข้อเสียเพิ่ม
- **ภาพ OG ตอนแชร์ลิงก์ไม่มีโลโก้** → ตรวจแล้วไม่ได้เป็นปัญหาอย่างที่กล่าวหา
